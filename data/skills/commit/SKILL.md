# 提交改动

按下面顺序做,不要跳步:

1. `git status` 和 `git diff` 看清改了**什么**。同时 `git log --oneline -5` 看一眼这个仓库
   既有的提交信息风格(中文还是英文、有没有前缀),**跟着它的风格写**,不要强加自己的习惯。
2. 判断这次改动**为什么**发生 —— 提交信息要写"为什么",不是"改了什么文件"。
   如果一个提交里混着几件不相关的事,提醒我是否要拆开。
3. 提交前扫一遍改动里有没有敏感内容:密钥、口令、内网地址(`192.168.` / `10.` / `172.16-31.`)、
   个人邮箱、主机名。**发现就先说,不要直接提交。**
4. 提交信息格式:`<一句话标题>`,空行,然后是分条说明(每条的"为什么"和影响)。
   标题不加句号,不用 "update" / "fix bug" 这种没信息量的词。
5. **不要自动 push**,除非我明确说了要推。
