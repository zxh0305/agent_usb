# 审查改动

目标是**找出会让改动出问题的地方**,不是给好评。按重要性排序报告,并说清每条的依据。

重点看这几类(按经验,出问题的概率从高到低):

1. **错误处理**:失败路径有没有被吞掉?异常捕获后是不是什么都没做?空值和边界条件?
2. **并发与状态**:有没有竞态、共享状态没保护、异步没等?进程被杀/中断时会留下什么?
3. **资源与清理**:临时文件、子进程、句柄有没有在异常路径上也释放?
4. **安全**:密钥/口令是否可能落到日志或文件?路径拼接是否可能被注入?
   **按宽度补齐、正则、编码**这类"看起来对但边界会错"的地方也要看。
5. **可读性**:命名、注释是不是在解释"为什么"。指出真正让人困惑的地方,别挑剔格式。

报告格式:每条给出 **文件:行号 → 问题 → 为什么是问题 → 建议**。
如果确实没发现问题,就直说"没发现实质问题",不要为了凑数编几条。
